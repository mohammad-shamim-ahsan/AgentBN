C1: # === Approach Overview for LLM ===
## Introduce the Approach
- Goal: Distinguish **undetected faults** and **cyberattacks** in DER (Distributed Energy Resources) systems
- Method:
  1. Construct a **special dependency graph** using a **virtual physical variable-oriented taint analysis (PVOTA) algorithm**
  2. Simplify the graph via **node pruning** based on context-dependent operations
  3. Derive **domain-specific patterns** bridging the semantic gaps between cyber and physical sides
- Use matched patterns as **prior nodes (evidence) in a Bayesian Network (BN)**
- BN Characteristics:
  - Automatic, generic network construction capable of handling any number of pattern-matching results
  - Uses **conditional probability distributions (CPTs)** to handle real-world uncertainties
    - Handles imperfect logs and insufficient data sources
  - Captures distinct DER system domain characteristics
  - CPTs are **expert-driven**
- Evaluation:
  - Tested on multiple case studies, covering failure incidents from:
    - FDI attacks  
    - System faults  
    - Memory corruption attacks

C2: # === Pattern definitions ===
## Overview
- Predefined patterns use three types of information:
  1. **PMU measurements** (field measurements)
  2. **Network packets (PCAP files)** to monitor network activities
  3. **DERMS application log** generated during program execution
- Dependency graph nodes:
  - Response message-related nodes
  - Dispatch message-related nodes
  - Other program variable-related nodes
- Only response and dispatch messages have corresponding field measurements and network packets.
- Patterns:
  - **Global patterns** → match abnormal system-wide event sequences (for response/dispatch)
  - **Local patterns** → track other program variables recorded only in application log

## Global Patterns (GPTN)
- GPTN1: ⟨Idn, Cna, Y⟩ → inconsistent network packet, deviation exists
- GPTN2: ⟨Idn, Cna, N⟩ → inconsistent network packet, deviation does not exist
- GPTN3: ⟨Cdn, Ina, Y⟩ → inconsistent application log, deviation exists
- GPTN4: ⟨Cdn, Ina, N⟩ → inconsistent application log, deviation does not exist
- GPTN5: ⟨Cdn, Cna, Y⟩ → logs consistent, deviation exists in field measurements
- GPTN6: ⟨Cdn, Cna, N⟩ → logs consistent, no deviation in field measurements
- GPTN7: ⟨Cdn, Ina, Y⟩R → inconsistent network packet, deviation exists
- GPTN8: ⟨Cdn, Ina, N⟩R → inconsistent network packet, deviation does not exist

## Local Patterns (LPTN)
- LPTN1: ⟨F/S, ED⟩ → expected deviation exists
- LPTN2: ⟨F, UED⟩ → unexpected deviation exists for float node
- LPTN3: ⟨S, UED⟩ → unexpected deviation exists for string node
- LPTN4: ⟨F/S, ⊤⟩ → log not available, or no deviation exists in the node
- LPTN5: ⟨Others, ⊤⟩ → function call or object, needed to maintain analytical flow

## Symbol Definitions
- **Idn / Cdn** → inconsistency / consistency between field measurements and network packet
- **Ina / Cna** → inconsistency / consistency between network packet and application log
- **Y / N** → deviation exists / deviation does not exist
- **∆ (Delta)** → degree of deviation: Low (L), Moderate (M), High (H)
- **ED / UED** → 
    - ED (Expected Deviation): deviation predicted based on upstream node or normal behavior
    - UED (Unexpected Deviation): deviation not predicted by upstream node or normal behavior; may indicate anomaly or attack
- **⊤ (top)** → unknown or not applicable
- **F / S / Others** → node type: Float, String, or Other (e.g., function call, object)
