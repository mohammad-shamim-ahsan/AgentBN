SUCCESS AND FAILURE DEFINITION
---------------------------------------------------
A scenario is considered successful only if all of the following conditions are satisfied:

1. The predicted root cause, defined as the argmax posterior of "Root_Causes", matches the "Ground Truth";
2. The posterior probability of the predicted root cause is at least 0.50; and
3. The difference between the posterior probability of the predicted root cause and that of the second most probable root cause is at least 0.20.

Therefore, a scenario is considered a failure if any one of the following conditions holds:

1. The predicted root cause does not match the "Ground Truth";
2. The posterior probability of the predicted root cause is less than 0.50; or
3. The difference between the posterior probabilities of the most probable and the second most probable root causes is less than 0.20.

## REFINEMENT OBJECTIVE

Identify the Bayesian Network with the lowest "failure_count" in the Analysis Memory and use it as the baseline for refinement.

Other BNs and the original flawed BN are provided only as historical context.

Only the parameter values in the the Conditional Probability Tables (CPTs) may be changed.

The graph structure, nodes, edges, states, parent lists, and parent_state_order are FIXED.

Make minimal necessary changes to the CPTs of the selected baseline BN. Modify as few CPTs as possible.

The failure scenarios in the Analysis Memory MUST be fixed under the evaluation definition.

The success scenarios in the Analysis Memory MUST be preserved under the same evaluation definition.

The "cpt_danger_report" field serves as fault-localization guidance rather than direct modification instructions.

Use the Analysis Memory to identify:
- failure scenarios that must be corrected,
- success scenarios that must be preserved,
- the dangerous CPTs reported in the "cpt_danger_report" field, which localize the most likely sources of the observed failures.

Refinement should prioritize modifying the reported CPTs and should remain restricted to them by default.

Modify a CPT outside the dangerous CPT report only if the reported CPTs alone cannot plausibly explain or resolve the observed failures based on the Bayesian Network structure, domain semantics, and the failure/success scenarios, which collectively indicate that an additional CPT also requires refinement.

The objective is to achieve the required improvement through the smallest sufficient set of CPT modifications while preserving successful behavior.

## CPT VALIDITY REQUIREMENTS

Whenever a CPT parameter is modified:
* Rebalance the remaining probabilities in the same CPT column.
* Ensure every CPT column sums to exactly 1.
* Ensure all probabilities remain within [0,1].
