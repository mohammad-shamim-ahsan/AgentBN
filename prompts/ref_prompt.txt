---------------------------------------------------
SUCCESS AND FAILURE DEFINITION
---------------------------------------------------

A scenario is considered successful only if all of the following conditions are satisfied:

1. The predicted root cause, defined as the argmax posterior of "{target_node}", matches the "Ground Truth";
2. The posterior probability of the predicted root cause is at least {min_confidence}; and
3. The difference between the posterior probability of the predicted root cause and that of the second most probable root cause is at least {min_margin}.

A scenario is considered a failure if any of the above conditions is not satisfied.

## REFINEMENT TASK

The selected baseline BN has already been determined by the workflow.

The total number of CPTs requiring refinement is known: {num_cpts_to_refine}, but their identities are unknown. This is a global constraint relative to the original deployed BN, not a per-iteration constraint.

The selected baseline BN may already contain refined CPTs, as indicated by {baseline_modified_cpts}. Consider these previously modified CPTs when selecting CPTs for further refinement.

The "cpt_danger_report" is produced by the refinement recommendation stage and defines the allowable CPT refinement search space.

If "reported_risk_level" is not "none", only CPTs listed in "dangerous_cpts" may be modified, provided that the report contains at least {num_cpts_to_refine} CPTs.

If "reported_risk_level" is "none", the recommendation stage could not identify any individual CPT with sufficient evidence for targeted refinement. This does not imply that the baseline BN is correct.

Only in this case, if the baseline BN still contains failure scenarios, use CPTs corresponding to the oracle-identified nodes ({oracle}) as a fallback refinement search space. Prefer minimal, well-justified modifications.

If "reported_risk_level" is not "none" but "dangerous_cpts" contains fewer than {num_cpts_to_refine} CPTs, use the reported CPTs as primary guidance and independently identify additional plausible CPTs from the oracle-identified nodes ({oracle}), based on the domain context, BN semantics, and recorded failure and success scenarios.

Use any "recommended_adjustment" directions as guidance, not as prescribed probability values.

The proposed CPTs must preserve the original "parent_state_order" and CPT dimensions.

Generate 3 independent refinement candidates.

Each candidate represents one complete BN refinement hypothesis and must specify exactly {num_cpts_to_refine} distinct CPTs as its global refinement set.

Previously modified CPTs may be retained with their current values, further refined, or excluded from a candidate, subject to the allowable refinement search space.

The candidates should represent distinct refinement strategies rather than minor numerical variations.

For each candidate, determine the parameter modifications using the selected baseline BN, "cpt_danger_report", domain context, BN semantics, and the recorded failure and success scenarios.

Prefer the smallest set of parameter modifications within the selected CPTs that corrects the recorded failure scenarios while preserving the recorded success scenarios.

Each candidate will be evaluated independently by a deterministic evaluation pipeline, and the best-performing candidate will be selected for the next iteration.

## CPT VALIDITY REQUIREMENTS

Any modified CPT must remain a valid conditional probability table.

Specifically:
- Every column represents a probability distribution over the child states.
- Every probability must lie within [0, 1].
- Every column must sum to exactly 1.
